# CodeMind X V2 — Capability Registry

> Runtime support matrix for the **current sandbox environment**. Statuses describe
> *environmental support*, not feature completion — a phase must still implement
> and evaluate a capability before it may be advertised.
>
> Statuses: **production** (live, backed by real service) · **local** (runs
> in-process / on-demand in this environment) · **fallback** (degraded in-process
> substitute available or planned) · **unavailable** (no support; must not be used
> or claimed).
>
> Never hide environmental limitations. Verified: Phase 0 governance addendum; updated Phase 3; updated Phase 4.

| **Adaptive Memory Engine** | `production` | Phase 9.5: five memory layers (project-rule / decision / concept / preference / correction) with scopes (user / repository / path / language / team), explicit-vs-inferred source, evidence refs, expiry. SECURITY: memory is created ONLY from user-authored origins (manual / user message / CODEMIND.md sync / inbox accept) — README/comment/tool-output/log/commit text can never become memory; secret-shaped content is refused before write; every change audited. Inferred proposals land in the Memory Inbox and NEVER activate without explicit Accept. Drift = honest heuristic term-presence + contradiction pairs vs the real workspace. Memory Used chip lists each used record with per-item disable (server-enforced exclusions). Incognito runs (no writes; reads user-toggleable). | **Orchestrator in the AI assistant (live agent thought chain)** | `production` | Phase 9.6: Agent composer mode executes the REAL Phase 9 engine inside the chat run and maps every live engine event onto the 8B/8C stage vocabulary, so the agents' actual work (planning, retrieval + real search/file rows, analysis, security, reasoning, critic) plays through the PROTECTED thought chain with zero changes to frozen surfaces (pacer/close/gates/anchoring byte-identical). The coding agent's proposal genuinely pauses the run at the engine approval gate; the chat approval card renders MID-RUN and its decision is delivered via `POST /api/assistant/approvals`, after which the run continues in the same stream. Memory (9.5) rides into the orchestrator request as labeled context data. Casual prompts keep the plain path; client disconnect cancels the run honestly; failed agents degrade exactly as the console does. Verified in-browser with the real gateway: full agent story, gate probe (loader 1.5s → full close → answer), approve-through-UI loop. |
